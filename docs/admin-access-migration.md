# 관리자 권한 관리

## 정책

일반 운영자는 기존처럼 회원·게임·모임·면접 자료를 공동 관리합니다. 역할별 업무 권한을 추가로 세분화하지 않습니다. 공개 면접 응답의 token·기간·허용 필드 규칙은 유지합니다.

관리자 식별은 이메일의 앞뒤 공백 제거·소문자 변환으로 통일하고 `admins/{정규화된 이메일}`을 조회합니다. 문서 역할이 `admin` 또는 `master`일 때만 운영자로 인정합니다. 역할 누락·잘못된 값·문서 부재·클라이언트의 서버 조회 실패에는 권한을 부여하지 않습니다. 개인 이메일의 bootstrap 예외는 없습니다.

| 요청 | 허용 범위 |
| --- | --- |
| 본인 문서 단건 조회 | 로그인한 본인. 문서가 없거나 역할이 잘못돼도 권한 확인을 위해 조회 가능 |
| 관리자 목록·운영 변경 이력 조회 | 마스터 |
| 일반 관리자 생성 | 마스터. 정규화된 이메일 ID와 `email` 일치, `role: "admin"`, 서버 시각 `createdAt`의 세 필드만 허용 |
| 일반 관리자 삭제 | 마스터. 기존 문서의 역할이 `admin`인 경우만 허용 |
| 관리자 문서 수정 | 웹 클라이언트에서는 모두 거부 |
| 마스터 생성·승격·강등·수정·삭제 | IAM 관리 경로에서만 수행 |

수정 금지는 전체 덮어쓰기·merge·배치 요청에도 적용됩니다. Console/Admin SDK는 IAM 권한으로 동작하므로 이 정책은 “Console UI만 허용”을 의미하지 않습니다. IAM 접근 권한은 별도 관리합니다. 일반 운영자에게 프로젝트 데이터 편집 권한을 함께 부여할 필요는 없습니다. Console 변경은 앱의 `auditEvents`에 자동 기록되지 않으므로 운영 기록을 남깁니다.

기존 관리자 문서는 역할과 정규화된 ID로 접근을 판단하며, 기존 문서 전체 스키마 이관을 강제하지 않습니다. 새 일반 관리자 문서만 위 생성 스키마를 강제합니다. UID 기반 이관·Custom Claims·인증 제공자 제한·email_verified 조건은 사용하지 않습니다. Emulator Design Lab의 합성 비밀번호 계정도 계속 사용합니다.

## 권한 변경 및 배포 확인

1. 올바른 프로젝트·DB에서 현재 배포 Rules와 관리자 문서를 조회합니다. 마스터·일반 운영자의 유효한 역할과 ID를 확인하고, 역할 누락은 의도한 권한을 확인한 뒤 보완합니다.
2. Firebase Console의 데이터 편집과 Rules 배포를 수행할 수 있는 IAM 관리 경로를 확인합니다. 앱의 `master` 역할 자체는 IAM 권한이 아닙니다. 기존 Rules 원문과 변경할 관리자 문서를 비공개 로컬 위치에 보관합니다.
3. 새 소스의 단위·Rules·Emulator UI 테스트를 실행합니다. 운영 데이터를 테스트 fixture로 사용하지 않습니다.
4. staging의 정상 마스터 문서를 먼저 준비하고 staging 빌드·Rules·Hosting을 반영합니다. Rules만 필요할 때는 `firebase deploy --project avalon-manager-staging --config firebase.staging.json --only firestore:rules`를 사용해 인덱스를 배포하지 않습니다.
5. staging에서 유지할 마스터의 실제 Google 로그인·일반 관리자 등록/삭제·공개 응답을 확인합니다. 운영은 `firebase.json`의 named database이며 staging은 `(default)`입니다.
6. 운영 전환은 별도 배포로 수행합니다. 정상 마스터 문서가 준비된 상태에서 클라이언트를 먼저 갱신하고 Rules를 별도로 배포할 수 있습니다. 최종 권한 제한은 새 Rules가 배포되어야 적용됩니다. 오래된 탭은 새로고침·재로그인으로 화면을 갱신하고 새 요청으로 확인합니다.

## 복구

권한 문서 문제라면 IAM 관리 경로에서 해당 계정의 정규화된 ID와 역할을 복구합니다. Rules 오류라면 해당 DB의 검토된 규칙을 재배포합니다. Hosting만 되돌려도 서버 규칙이나 관리자 문서는 되돌아가지 않습니다. 개인 이메일 예외를 다시 넣거나 모든 요청을 허용하는 규칙을 복구 기본값으로 사용하지 않습니다.
