# 개발 가이드

## 구조와 책임

React/Vite 단일 페이지 앱입니다. `src/main.tsx`가 앱을 시작하고 `src/App.tsx`가 인증, 관리자 화면 틀, lazy route를 구성합니다. `/interview/:token`은 공개 지원자 페이지이며 나머지 화면은 관리자 인증을 거칩니다.

| 위치 | 책임 |
| --- | --- |
| `src/components/` | 페이지, 패널, 폼, 모달. 기능 이름으로 검색할 수 있습니다. |
| `src/hooks/` | 화면 상태, 사용자 작업, 구독 수명과 알림 |
| `src/domain/` | Firebase와 UI에 의존하지 않는 계산, 정책, CSV 변환 |
| `src/services/` | Firestore 읽기/쓰기, 트랜잭션, 외부 I/O |
| `src/types.ts` | 저장 문서와 주요 도메인 타입 |
| `src/lib/` | Firebase 초기화, 배치 쓰기, CSV 다운로드, 표시 유틸리티 |
| `src/scenario-lab/` | Firebase 없이 실제 UI 컴포넌트를 렌더링하는 fixture 앱 |
| `scripts/`, `tests/` | Emulator 실행/seed/reset, 번들 검사, Playwright 시나리오 |

일반적인 변경은 페이지 → 해당 hook → domain/service 순서로 따라가면 됩니다. 기존의 간단한 CRUD는 hook에 남아 있으며, 여러 문서를 다루거나 여러 화면에서 쓰는 데이터 작업은 service가 소유합니다. 모든 기능에 새 계층을 만들 필요는 없습니다.

면접의 구독과 문서 결합은 `useInterviewRoundData`, 수동/자동 배정과 낙관적 갱신은 `useInterviewAssignmentLogic`에 있습니다. 상위 `useInterviewRoundLogic`은 회차·일정·지원자·면접관 작업을 연결합니다. `useInterviewNoteLogic`은 노트 자동 저장과 revision 충돌을 별도로 관리합니다. `interviewPolicy`가 활동 상태, 진행 상태와 현재 확정 안내의 유효성을 판정합니다.

면접 서비스는 회차(`roundsService`), 일정(`schedulesService`), 실제 배정(`schedulingService`), 지원자, 면접관, 기록, 회원 등록으로 나뉩니다. `interviewsService.ts`는 이 공개 API를 모아 내보내는 진입점입니다. 배정 변경은 잠금·접근 문서·이력도 함께 바꾸므로 기존 트랜잭션 경로를 재사용하세요.

면접 메시지 기본 문구는 `domain/interviews/messages.ts`에서 관리합니다. 새 회차에는 여섯 종류의 기본 문구를 저장하고, 기존 회차는 저장된 사용자 문구를 유지합니다. 면접 설정의 각 `기본 문구 적용`은 해당 초안만 교체하며 저장 시 반영됩니다. 선발·미선발 안내는 이름만 자동 치환하며, 기본 선발·미선발 문구의 `[모집 기수]`, 선발 문구의 `[은행명 및 계좌번호]`와 `[예금주]`는 자동 치환하지 않는 수동 편집 표시입니다. 운영자가 저장 전에 직접 바꾸며, 기본 회비 20,000원도 필요하면 편집합니다. 지원자 상세와 선발 상세는 같은 기본값 해석·치환 함수를 사용합니다.

## 데이터에서 유지해야 할 구분

- `SessionGroup`은 조 편성 중의 **attendee ID**, `StoredSessionGroup`은 저장된 **member ID**를 담습니다. 변환은 `domain/attendance/sessionGroups`에서 합니다. `DailyPlannings`의 저장 타입은 `domain/attendance/dailyPlanning`에 있습니다.
- 모임 계획(`DailyPlannings`)과 확정 기록(`sessions`)은 별도 문서입니다. 현장 화면과 기록 화면이 함께 사용하므로 이름 변경이 게임 기록 같은 다른 필드를 덮어쓰지 않아야 합니다.
- `Session.boardMemberIds`가 없으면 과거 형식의 데이터이며 현재 회원 정보로 보완합니다. `[]`는 당시 임원이 없었다는 명시적 기록입니다. CSV 변환과 통계에서 이 차이를 유지합니다.
- 오래된 세션에는 game ID 대신 게임명이 들어 있을 수 있습니다. 현재 조회와 내보내기의 fallback은 유지합니다.
- 면접 지원자의 `scheduleId`는 `undefined`(기존 회차 기반 데이터), `null`(미배정), 실제 ID(일정 배정)를 구분합니다. 실제로 사용되는 이관 경로와 공개 응답 fallback을 일괄 삭제하지 마세요.
- 통계 학기 경계는 3월/9월, 면접 후 회원 등록 기본 학기는 2월/8월 기준입니다. 게임 목록과 통계의 난이도 구간도 다릅니다. 이름이 비슷하다는 이유만으로 합치지 않습니다.
- 자동 조 편성은 `domain/matching/groupSizing.mjs`로 정원을 먼저 결정하고 `personalUtility.ts`로 요청 → 운영진 → 개인 효용을 비교합니다. `autoAssignAlgorithm.ts` 탐색과 개인 점수 화면은 같은 평가기를 사용합니다. 이전 `groupCostFunction`/`groupCostContext`는 과거 모델의 비교용 코드이며 현재 편성·점수 화면에서 사용하지 않습니다.

일일 조 편성의 `편성 평가`는 `CostEvaluationModal`에서 조·조원을 선택하는 레이아웃으로 표시합니다. `attendanceButtonStyles`의 청회색 실행·투명 종료 버튼을 실제 화면에서 사용합니다. 개인별 지표는 조별 값을 따로 보호하지 않고 `combineScores`로 전체 배치의 보호·완화 값을 계산합니다. 모달은 native dialog로 포커스를 제한하고 Esc/닫기 후 이전 버튼으로 돌려주며, 미배정·미등록·결석 인원과 조회 불가 상태를 안내합니다. 출석 카드·조 카드·배치 및 저장 계약은 이 디자인 변경의 대상이 아닙니다.

개인 관점의 자동 편성은 [조 인원 구성 모델](group-sizing-model.md)과 [개인 효용 모델](group-utility-model.md)을 따릅니다. 요청 완화·과거 이력 감쇠·환산 보호를 조정하고, 독립 수식 대조·오프라인 모의 편성·전체 화면 회귀 검증을 수행했습니다. 현재 파라미터는 초기 운영값이며 실제 만족도로 추정한 값은 아닙니다. 배포 및 환경 확인 절차는 [운영 가이드](operations.md)를 따르세요.

- `lib/runAutoAssignment`가 브라우저 Worker를 실행합니다. 명단·이력·날짜·조 설정 변경 또는 화면 종료 시 취소하며, 취소된 결과는 적용하지 않습니다. 출석 명단·회원 명부·세션 이력의 조회가 모두 완료되고 오류가 없을 때만 편성/내보내기를 실행합니다.
- 수동 배치는 고정합니다. 해당 조의 수동 인원수를 정원의 하한으로 반영한 뒤, 미배정 등록 참석자만 이동합니다. 결석자는 자동 대상에서 제외하며, 중복 회원이나 조 안의 미등록·결석 인원은 오류로 안내합니다.
- 한 명 교환에 더해, 함께 배치된 동반 요청 쌍을 다른 조의 이동 가능한 두 사람과 한 번에 교환합니다. 양쪽 요청 당사자 모두 미배정에서 편성된 경우만 이동하며, 수동 고정·정원·요청 → 운영진 → 전체 개인 효용 비교를 유지합니다. 시작 배치마다 쌍 교환 평가를 최대 2,000회로 제한하며 전역 최적성을 보장하지 않습니다.
- 동반 요청은 `companionRequests`의 공통 상대 해석을 사용합니다. 전체 이름과 세 글자 한글 이름의 성을 뺀 이름을 부분 문자열로 찾으며, 앞뒤 띄어쓰기나 조사·호칭 허용 목록은 사용하지 않습니다. 전체 이름이 나온 부분은 짧은 이름으로 다시 해석하지 않습니다. 다른 단어에 들어 있는 동일 글자도 후보로 잡힐 수 있습니다. 그날 참석 후보가 여러 명이면 해당 요청을 보류합니다. 알림을 누르면 기존 디자인의 별도 모달에서 운영진이 한 사람을 확정하거나 미확정으로 되돌립니다. 선택은 계정별 브라우저 편성 임시 저장에 보관하며 원문·후보 변경 시 다시 확인합니다. 확인된 불참 상대는 점수에서 제외하고 안내합니다. 미충족 요청은 관련 조에 표시하며 수동 조정 후 현재 배치로 다시 계산합니다. 인원 규칙 완화 안내는 마지막 자동 편성의 입력·결과가 유지되는 동안 화면 상단에 표시합니다.
- 성별 기타/미상과 학번 누락은 해당 개인과 다른 사람의 해당 항목 계산에서 제외합니다. 과거 이력은 편성 날짜보다 앞선 확정 세션만 사용하며 재회 비용의 감쇠는 개인별 실제 참석 순서입니다. 기존 재회 경고는 날짜 제한 후 전체 최근 3회 기준을 유지하는 별도 안내입니다.
- 진단 JSON의 모델은 `personal-utility-v3-protect-then-attenuate-provisional`입니다. `assignmentDiagnostics`가 `schemaVersion: 1`의 현재 배치·실제 자동 편성 기록·개인별 평가와 분포·수동 조정 비교를 생성합니다. 추출은 Worker를 다시 실행하지 않으며, 화면 메모리에 실행이 없으면 현재 평가와 기록 없음 상태만 담습니다. 요청 곱은 문자열로 직렬화하고 사람/조는 파일 내 임시 번호를 사용합니다. 상세 스키마 의미와 비교 제한은 [개인 효용 모델](group-utility-model.md)의 앱 연결 범위를 참조하세요. 환산 보호는 완화 전 순효용과 완화 비중을 반영한 전체 평균 및 고정 척도를 사용합니다. 보호 후 기여분에 완화를 적용하고, 빠진 재회 비용은 별도 차감합니다. 보호 계수 1~2와 완화 이후 실제 개선 중요도를 구분합니다. 교환 후보 평가와 점수 창에서 조별 보호 점수를 합산하지 않고 전체 보호를 다시 계산합니다. 이전 v2와 점수식이 달라 같은 요청 배치의 점수를 직접 비교하지 않으며 탐색 이력을 무작위 표본으로 해석하지 않습니다. 저장 컬렉션/Rules/ID 변환 계약은 변경하지 않습니다.

## 개발 환경과 검증

모임 공지·음료 이미지 추출은 `services/captureService`에서 처리합니다. `html-to-image`로 PNG Blob을 만들고 Blob URL을 다운로드 링크에 전달합니다. Safari의 `data:` URL 다운로드 문제를 피하기 위한 변경이며, 확인창에서 브라우저가 URL을 사용할 시간을 주기 위해 클릭 직후 해제하지 않고 60초 뒤 해제합니다. 단위 테스트는 Blob 전달·지연 해제·생성 실패 시 다운로드 방지를 검증하며 실제 iPhone/iPad Safari의 저장 완료 여부는 별도 확인이 필요합니다.

이미지 추출 브라우저 회귀 검사는 `tests/capture/`의 합성 fixture에서 실제 `MeetingCanvasTab`·`captureBoard`·이미지 렌더러를 사용합니다. `npm run test:capture`로 Chromium과 iPhone 13·iPad Pro 11 설정의 WebKit에서 실행하며 CI에도 포함합니다. 최초 실행 전 `npx playwright install chromium webkit`으로 브라우저를 설치하세요. Scenario 모드의 Vite에서 실행하고 Firebase는 초기화하지 않습니다. PNG 저장 완료·파일명·헤더·해상도·색상/밝은 내용·페이지 유지와 오류 부재를 확인합니다. 외부 Google Fonts는 빈 CSS로 대체해 네트워크 변동을 배제하므로 외부 글꼴 가용성을 검증하지 않습니다. Playwright 기기 설정은 에뮬레이션이며 실제 iOS/iPadOS Safari의 다운로드 확인창·파일 앱 저장 확인을 대체하지 않습니다.

회원 세부 정보의 메모는 관리자 편집 모드 토글과 관계없이 `수정 → 저장/취소`로 바로 편집합니다. 로그인한 기존 운영 계정의 members 쓰기 권한을 사용합니다. 동아리원 관리·모임 진행·세션 기록이 같은 `MemberProfileModal`을 사용하며 최신 members 구독으로 표시를 갱신합니다. `useMemberMemo`는 회원별 초안을 격리하고 저장 실패 시 입력을 유지합니다. `memberMemoService`는 트랜잭션에서 편집 시작 시의 메모와 현재 값을 비교한 뒤 memo 필드와 `member.updated` 감사 기록만 함께 저장하며, 다른 필드를 덮어쓰거나 삭제된 회원을 다시 만들지 않습니다. 동시 수정 충돌 시 입력을 보존하고 사용자가 최신 메모를 불러와 다시 편집할 수 있습니다.

동아리원 명부의 PC 레이아웃(md 이상)은 관리자 편집 모드에서 체크박스·순번·이름/학번 영역 전체를 하나의 선택 label로 사용합니다. 체크박스 크기는 유지하며 상세 기록·수정·삭제 버튼은 선택 영역 밖에 둡니다. 모바일은 기존 체크박스 선택 동작을 유지합니다.

설정의 관리자 권한 삭제는 멤버 삭제와 같은 `ConfirmDeleteModal`에서 대상 이메일과 접근 권한 상실을 확인한 뒤 실행합니다. 삭제 중에는 중복 실행·취소를 막고, 실패하면 확인창을 유지해 재시도할 수 있습니다. 마스터의 삭제 불가 표시와 일반 관리자의 삭제 버튼 미노출은 유지합니다. 관리자 표는 이메일을 줄바꿈하고 관리 열의 너비를 확보하여 모바일에서도 삭제 버튼을 표시합니다.

관리 화면 공통 오류 안내의 `새로고침` 버튼은 현재 URL을 유지한 채 페이지 전체를 다시 불러옵니다. 특정 메뉴로 이동하는 기능이 아니며, 배포 후 구버전 탭의 화면 파일 로딩 실패도 최신 진입 파일을 다시 받아 복구할 수 있습니다. 오류 발생 자체를 예방하거나 자동으로 새로고침하는 기능은 포함하지 않습니다.

게임 라이브러리의 수정 폼은 `GamesPage`에서 입력/저장 상태를 유지하고 `GameList`의 선택한 카드 행 아래에 하나만 표시합니다. 카드 그리드의 1/2/4열에 맞춰 수정 영역의 CSS 순서를 지정하므로 열 수를 바꾸면 수정 영역 순서도 함께 조정합니다. 모바일에서는 선택 카드 바로 아래에 열리고, 새 게임 추가는 기존 상단 폼을 사용합니다. 게임 저장 필드와 감사 기록 경로는 동일합니다.

게임 수정은 난이도 `0`(미평가)과 인원 `0`(미지정)을 그대로 유지합니다. 난이도는 0 또는 1~5를 입력합니다. 가능/적정 인원은 폼과 CSV가 공통 검증을 사용하여 0 이상의 정수만 허용하며, 두 경계가 모두 지정됐으면 최소가 최대보다 클 수 없습니다. CSV의 기존 `5명` 숫자 접두사와 미지정 값 해석은 유지합니다. 인원 오류가 있으면 행 번호와 이유를 안내하고 파일 전체를 저장하지 않으므로, 수정 후 다시 가져옵니다. 기존 저장 데이터나 Firestore 규칙의 일괄 이관은 하지 않습니다.

동아리원 관리의 `휴면 시작 학기`는 마지막 활동 학기가 아니라 통계에서 활동 인원 제외를 시작하는 학기입니다. 일괄 전환과 개인 정보 수정은 같은 명칭을 사용하며, 미래 학기를 넣어도 명부 상태는 저장 즉시 휴면으로 바뀝니다. 다음 학기 기본값은 유지합니다. 휴면 명부는 시작 학기 최신순으로 정렬하고, CSV의 기존 `휴면학기` 열 이름과 저장 필드 `dormantSemester`는 호환성을 위해 유지합니다. 활동 복원·출석 등록·면접의 기존 부원 복원 연결은 이 값을 비우므로 다회 휴면 이력을 보존하는 모델은 아닙니다.

면접 진행 기록 화면은 닫기 또는 조치 필요 이동 전에 대기 중인 저장과 마지막 입력의 저장을 확인합니다. 확인 중에는 입력과 다른 작업을 잠시 막고, 실패·수정 충돌이면 입력과 화면을 유지해 재시도/충돌 해결을 안내합니다. 변경 없는 기록은 서버 쓰기 없이 닫힙니다. 면접 노트의 대기 작업·구독 응답은 지원자와 회차가 바뀌면 이전 세대의 작업으로 구분하여 새 지원자의 입력이나 저장 상태를 읽거나 수정하지 않습니다.

환경별 연결 대상과 배포 명령은 [운영·인수인계](operations.md)를 참조하세요.

- 빠른 화면 확인: `npm run scenario-lab` → `http://127.0.0.1:5174/design.html`. fixture 상태는 `fixtures.ts`, 화면 구성은 `ScenarioPages.tsx`, 선택기는 `ScenarioLabApp.tsx`에 있습니다. 상태를 추가하면 `tests/scenario-lab/scenario.spec.ts`도 확인합니다.
- 실제 hook/service/규칙 확인: `npm run design-lab`. Java 21을 `JAVA_HOME`에 설정하거나 Windows에서 `npm run demo:setup`을 한 번 실행합니다. 시작할 때 데이터가 초기화되며, 실행 중에는 `npm run demo:reset`으로 다시 seed할 수 있습니다.
- 기본 확인: `npm run check`는 lint, 타입, 단위 테스트, 운영 빌드를 실행합니다. Vitest는 `src/**/*.test.{ts,tsx}`를 대상으로 하며 `test:unit`은 Emulator 규칙 테스트를 제외합니다.
- Firestore 규칙/권한 변경: `npm run test:rules`. UI 연결 변경: `npm run design-lab:test`. fixture UI/반응형 변경: `npm run scenario-lab:test`. Playwright를 처음 쓸 때 `npx playwright install chromium`이 필요할 수 있습니다.
- Design Lab 브라우저와 CI 실행 시간대는 `Asia/Seoul`입니다. 합성 모임 계획도 한국 날짜로 seed합니다. 세션 삭제·조 이름 회귀 테스트는 오늘과 다른 고정 날짜를 저장한 뒤 모임 화면에서 그 날짜를 명시적으로 선택하여 UTC/한국 자정 차이에 의존하지 않습니다.
- `scripts/emulator-runtime.mjs`가 Design Lab과 규칙 테스트의 Java 탐색 및 Firebase CLI 실행을 함께 담당합니다. `seed-demo.mjs`의 프로젝트/호스트 검사는 로컬 데이터 초기화를 보호하므로 유지합니다.

도메인 테스트는 구현 옆에 둡니다. CSV나 데이터 변환을 바꾸면 정상 입력뿐 아니라 기존 저장 형식과 빈 값의 의미를 확인하세요. JSX 이동만을 확인하는 테스트는 추가하지 않습니다.

## 나중에 다시 시작할 때

Codex/ECC의 작업 크기별 진행 방식, 스킬 선택과 검증 명령은 [에이전트 작업 방식](agent-workflow.md)을 따릅니다. ECC 없이도 아래 개발 절차와 저장소 명령을 그대로 사용할 수 있습니다.

1. `npm ci` 후 변경할 기능의 위 시작점을 읽습니다.
2. 현재 동작은 Scenario Lab 또는 Design Lab에서 확인합니다.
3. [코드 지식 그래프 운영](knowledge-graph.md)에 따라 `node scripts/graphify.mjs status`로 최신성을 확인하고 Graphify의 query·path·explain·affected로 연결을 좁힌 후 소스를 확인합니다. 일반 미커밋 작업은 마지막 정상 그래프와 실제 diff를 함께 검토합니다. 완료된 작업에서 구조를 갱신하고 업무 의미·문서·권한 변경에는 의미 분석과 필수 사례 검토도 수행합니다.
4. 변경한 경계에 맞는 검증을 선택하고, 구조나 운영 방법이 달라졌을 때 이 가이드를 갱신합니다.

Graphify의 검증된 `graphify-out/` 허용 목록만 Git에 공유하며 설치 경로와 임시 산출물은 제외합니다. `agent_docs/`는 Git 제외된 선택적 과거 기록입니다. 새 clone에서 필요한 개발·운영 정보는 이 `docs/`와 README를 기준으로 합니다.

## 출석 등록·세션 삭제와 조회 오류

- 출석 CSV 미리보기는 원본 행 번호를 유지하며 이름·학번·음료·뒤풀이·요청을 수정할 수 있습니다. 동명이인은 닉네임·가입학기로 명시적으로 선택합니다. 확인 열과 회원 선택 목록은 `2024-1`을 `24-1`로 표시하여 학기까지 구분하며 저장된 가입학기는 유지합니다. 열 연결·행 수정·명부 변경 시 기존 명단 교체와 미등록 가져오기 확인을 다시 받으며, 저장 직전 회원 명부를 다시 읽어 선택을 검증합니다. 미등록은 별도 확인 후 저장하며 회원 등록 전에는 조 배정하지 않습니다.
- 새 `Attendee.memberId`는 선택한 회원 ID, `null`은 명시적 미등록입니다. 필드 부재는 기존 이름·학번 접두사 조회와 미매칭 fallback을 유지합니다. 출석 화면·자동 편성·계획/확정 세션 변환은 같은 해석을 사용하며 삭제된 명시적 ID를 다른 동명이인으로 다시 연결하지 않습니다. 출석에서 회원을 등록하면 정정한 이름·학번과 새 memberId를 회원 생성과 같은 배치에 저장합니다.
- 미배정 명단은 모바일 50dvh·데스크톱 70dvh로 높이를 제한하고 헤더 아래 목록만 스크롤합니다. 목록 내부 휠과 드래그 자동 스크롤은 페이지로 전파하지 않으며, 잘려 보이지 않는 목록 아래에는 카드를 놓을 수 없습니다.
- 출석 카드의 멤버 추가는 확인 폼을 열며 저장 전에는 쓰지 않습니다. 성별은 직접 선택하고 학번 미입력 시 임의 값을 만들지 않습니다. 등록 서비스는 현재 명부와 중복을 확인하고, 회원 생성과 정정한 출석 이름·학번을 같은 배치에 저장합니다. 가입 학기는 일반 회원 등록과 같은 3월/9월 기준이며 면접 등록의 2월/8월 기준은 유지합니다.
- 모임 시작은 실제 조에 들어간 참석자만 편성됨으로 변경합니다. 미배정자의 대기·결석 상태는 유지합니다.
- 세션 삭제는 해당 sessionId를 참조하는 DailyPlannings의 연결 필드만 함께 제거합니다. 모임의 조·음료·요청·이전 버전은 유지하며, 버전 복원은 현재 연결만 사용하므로 삭제된 연결을 되살리지 않습니다. 연결 조회 실패나 배치 실패는 삭제 성공으로 처리하지 않습니다.
- 모임 진행 기록 관리에서 이전 버전 선택은 같은 모달의 상세 화면으로 전환합니다. 버전 요약과 복원/확인 버튼은 스크롤 밖에 두고 조·참석자 상세만 스크롤합니다. 버전 목록으로 돌아가면 목록 위치와 선택 항목의 포커스를 복구하며, Esc는 복원 확인 취소 → 버전 목록 → 기록 목록 순서로 돌아갑니다.
- useFirestore는 error와 retry를 제공하고 조회 실패 시 지속되는 알림과 다시 시도 버튼을 표시합니다. 재구독할 때 로딩과 데이터를 초기화합니다.
- members/games/sessions Rules는 새 문서의 핵심 필드·타입·enum을 검사합니다. 기존 문서는 변경한 필드만 검사하므로 누락된 과거 필드를 한꺼번에 채우지 않아도 휴면 전환 등의 작업이 가능합니다. 중첩 배열 항목 전체의 도메인 검증이나 모든 legacy 문서의 자동 이관을 의미하지 않습니다.
- 기본 개발 명령은 npm run dev(Emulator Design Lab)이며 운영 연결은 npm run dev:prod로 명시합니다. 세션 동시 편집 병합, export, 보관 정책은 별도 기능 경계입니다.

## 전시 집계와 공개 조회

`src/domain/exhibition/collection.ts`는 정해진 기간의 운영 세션에서 개인별 기록과 이름 조회 키를 계산합니다. 날짜는 한국 시간으로 해석하고 공동 플레이는 같은 조에서 나온 게임으로 집계합니다. 공개 기록은 원본 게임 ID에서 파생한 키로 집계하고 `gamePins`에는 재사용할 그림의 키를 저장합니다. 그림은 관리자의 지정 값을 우선하고, 지정이 없으면 유일한 이름 일치로 찾습니다. 이미지가 없는 게임도 이름과 플레이 내역을 표시합니다. 관리자가 제외한 게임은 집계에서 빼고, 원본에서 삭제된 게임이나 기본 그림 연결이 없는 게임은 관리자 진단에서 확인할 수 있습니다.

부원 화면은 `exhibitionAccess/{exhibitionId}`에서 현재 데이터 묶음 ID를 읽은 뒤 `generations/{generationId}/names/{nameKey}`와 `profiles/{profileId}`를 개별 조회합니다. 이름 조회 직후 선택한 후보의 프로필에는 직전에 확인한 묶음 ID를 한 번 재사용합니다. 서버가 묶음 교체로 조회를 거부하면 현재 묶음을 다시 확인합니다. Firestore Rules는 현재 활성 데이터 묶음의 개별 조회를 허용합니다. 이름 키는 이름을 입력해 계산할 수 있으므로 전시 열람에 로그인은 필요하지 않습니다. 쓰기는 기존 `admin`과 `master` 권한을 사용합니다.

[원본 운영 앱](https://avalondgu.web.app/), [전시 설정 사이트(AVALON Studio)](https://avalon-collection-studio.web.app/), [공개 전시](https://avalon-collection.web.app/)는 같은 운영 Firestore 데이터베이스를 사용합니다. 원본 운영 앱에서 세션 저장은 원본 데이터 커밋으로 완료됩니다. 공개 기록은 기본적으로 수동 반영합니다. Studio의 **공개 설정 → 공개 기록 자동 반영**을 저장하면 전시 설정 문서의 `autoPublish`에 기록됩니다. 값이 없거나 꺼져 있으면 로그인, 탭 복귀 또는 설정 저장만으로 발행을 시도하지 않습니다. 원본 운영 앱의 **설정 → 공개 전시**에서 반영 상태를 확인하고 수동 반영 요청 또는 Studio로 이동할 수 있습니다. Studio에서도 **Publish records**로 같은 작업을 요청할 수 있습니다. 전시가 공개로 설정되어 있고 자동 반영을 켜면 원본 운영 앱의 관리자 탭은 세션·회원·게임 변경을 감시합니다. Studio 관리자 탭은 전시 설정에서 발생하는 반영 요청을 감시합니다. 두 앱은 자동 반영을 켜거나 다시 접속할 때 원본을 대조합니다. 공개 전시의 이름 조회는 발행된 기록만 읽습니다. 공개용 기록을 만드는 데 사용한 원본의 지문은 `exhibitionSync/source`에 저장하고, 최신 버전만 공개 조회 대상으로 전환합니다. 공개 중인 컬렉션에는 핀 설명과 이미지 변경이 실시간으로 반영됩니다.

정기모임 세션의 날짜·조원·게임 변경과 공개 결과에 쓰이는 이름·학번·게임 제목 변경이 발행 대조의 대상입니다. 짧은 간격의 변경은 묶고, 수동 반영에서 결과가 같으면 공개 기록을 다시 쓰지 않습니다. 작은 변경은 기존 세대에서 달라진 이름 조회와 개인 컬렉션만 내용 버전과 함께 트랜잭션으로 갱신합니다. 공개 화면은 세대나 내용 버전이 바뀔 때 열린 컬렉션을 새로 읽습니다. 첫 발행과 큰 변경은 새 세대를 준비한 뒤 한 번에 공개합니다. 여러 탭은 적용 버전과 준비 위치를 트랜잭션으로 확인하므로 이미 처리한 변경을 다시 쓰지 않습니다. 이전 세대 정리는 발행과 별개로 최대 하루 한 묶음씩 처리하고, Firestore 사용 한도 오류가 나면 해당 탭은 30분 동안 발행 재시도를 미룹니다.

부원용 화면은 `exhibition/`의 별도 Vite 진입점에서 빌드합니다. `npm run exhibition:dev`는 로컬 Firestore Emulator(127.0.0.1:8080)의 전시 데이터만 조회합니다. 전시 ID 기본값은 `avalon`이며 필요 시 `VITE_EXHIBITION_ID`로 지정합니다. `npm run exhibition:build`는 `exhibition/dist/`에 운영 연결용 정적 파일을 생성하고, `npm run exhibition:build -- --mode staging`은 staging 연결용 파일을 같은 위치에 생성합니다. 기존 운영 앱 빌드와 배포 디렉터리는 별개입니다. 핀·글꼴·배경은 원본 HTML에서 바이트 그대로 추출했으며 이름 조회와 개인 기록은 Firestore에서 읽습니다.

운영 전시 관리자는 [AVALON Studio](https://avalon-collection-studio.web.app/)이며 소스는 `exhibition-admin/`에 있습니다. `npm run exhibition:admin:dev`는 로컬 Auth·Firestore Emulator를 사용하고, `npm run exhibition:admin:build`는 `exhibition-admin/dist/`로 빌드합니다. Studio의 **Exhibit text**는 `exhibitionCopy/{exhibitionId}`에 저장합니다. **Games and pins**에서는 게임별 설명, 이미지 URL 또는 파일을 지정할 수 있습니다. 파일은 브라우저에서 최대 512px·192 KiB WebP로 변환합니다. 버전은 `exhibitionPinAppearance/{exhibitionId}`에, 바이트는 그 하위 경로 `exhibitionPinAppearance/{exhibitionId}/exhibitionImages/{gameKey}`에 같은 트랜잭션으로 저장합니다. 공개 앱은 활성 버전을 화면에 필요할 때 읽습니다. 게임별 설정이 없으면 기존에 연결된 그림과 설명을 사용합니다. 공개 기록이 새로 발행되면 열린 컬렉션은 현재 날짜와 동료 선택에 맞춰 갱신됩니다.

게임 순위는 개인 전체 기록의 조별 플레이 횟수와 최근 플레이일로 한 번 계산합니다. 날짜와 동료 필터는 같은 순위를 유지하며 해당 게임만 보여 줍니다. 동료 목록은 함께한 조 수, 최근 날짜, 서로 다른 공동 게임 수, 가나다순으로 정렬합니다. 과거 전시 데이터는 관리자 화면의 다시 반영을 실행하면 조별 집계로 갱신됩니다.

Studio의 **Needs attention**은 기본으로 현재 발행된 개인별 컬렉션에 등장하는 게임 중 이미지나 설명이 없는 항목을 보여 줍니다. 발행 시 게임 키를 관리자용 진단 문서에 함께 기록합니다. 이 정보가 없는 기존 버전은 작업 현황을 열 때 해당 버전의 컬렉션에서 게임 키를 모읍니다. **운영 게임 목록 전체**로 바꾸면 세션 기록에 없는 게임도 확인할 수 있습니다. 기본 그림과 설명이 있으면 등록된 것으로 계산하며 링크 응답은 일괄 검사하지 않습니다. 각 항목은 게임 편집 화면으로 연결됩니다.

공개 컬렉션의 핀은 위치를 저장하지 않습니다. 브라우저가 표시할 게임의 순위와 핀 영역 너비로 줄을 계산합니다. 상대 크기와 회전은 순위에서 계산합니다. 이름을 입력하기 시작하면 공개 버전을 미리 조회하고, 제출하면 컬렉션 스켈레톤을 표시합니다. 한 사람을 찾은 경우 이름과 개인 기록 조회에 전체 3초를 사용합니다. 동명이인 선택 후 프로필 조회와 컬렉션 직접 열기는 각각 3초이며, 응답이 늦으면 다시 시도 아이콘을 표시합니다.

Studio의 한국어·영어 선택은 브라우저에 저장합니다. 설정 화면과 게임 이름에 적용하고 작성된 전시 문구와 핀 설명은 저장된 언어로 표시합니다. 게임 검색은 두 언어를 모두 사용합니다. 핀 편집의 고급 설정에서 외부 HTTPS 이미지를 연결하거나 게임을 공개 전시에서 제외할 수 있습니다. 전시 제외는 공개용 집계에만 적용합니다. 공개 설정·게임과 핀 편집·전시 문구는 편집 내용을 공유하며, 마지막 저장 상태와 다른 설정이 있을 때 저장·취소를 표시합니다. 취소는 편집 중인 값을 마지막 저장 상태로 되돌리고, 핀 편집에서 실행하면 선택한 게임과 검색어도 지웁니다.
